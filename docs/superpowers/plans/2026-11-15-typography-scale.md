## Working contract and acceptance criteria

1. Canonical CSS owns separate body/heading mobile and desktop bases and ratios. Each family has six named steps, xs/s/m/l/xl/xxl, corresponding to -2/-1/0/1/2/3. Each endpoint is calculated independently, then interpolated with inherited `--fluid`. Use repeated multiplication/division, no `pow()`, Sass or JavaScript sizing engine. Initial comparison inputs are body 1rem/1.125rem, headings 1.5rem/1.6875rem, and ratios 1.2/1.333 for each family. Heading bases are illustrative 1.5 times the body comparison bases; their largest step approximates the current display range. These are candidates, not approved production values.
2. Recalculate derived scale/semantic tokens at `:root` and explicit `.ds-type-scope` boundaries. Root input edits update all scopes; valid local input overrides on an explicit boundary update only that scope. Optional per-step `--design-type-{family}-{step}-{min|max}` overrides resolve there and affect only that step. Existing viewport bounds remain root-only. Keep the shipped native/trigonometric/static engine unchanged. Expose candidate semantic sizes through namespaced Tailwind tokens without remapping existing production utilities. Keep body role sizes at least the current body-xs floor; captions and controls remain explicit existing-size exceptions.
3. The existing guide gains a typography-scale section with current/candidate semantic comparisons, input identities, computed min/current/max scale measurements, a local override specimen and long internal EN/AF reading samples. Reuse the measurement hook without JS sizing. Show current unitless leading/tracking alongside candidate sizes; do not adopt x-height leading or proportional tracking in this batch. Font selection remains in existing body/display tokens. The isolated application preview and registration remain on production roles.
4. Extend the numeric source gate without weakening existing rules. Require unique literal positive rem bases, unitless ratios >=1, and finite positive derived endpoints across all six steps. Preserve ordered fluid bounds and valid descending/equal step endpoints. Test missing/duplicate/invalid/overflow inputs. Runtime CSS overrides retain CSS's normal validity rules; the gate is not a general parser or runtime validator.
5. Prove source/HTML contracts before implementation, arithmetic against an independent reference, and actual computed CSS across native/trigonometric/static paths, bounds/midpoints, root sizes 16/32, narrow parents, root/local/step override propagation and sibling isolation. Review long EN/AF wrapping, true doubled text independently of root-size simulation, local font availability, fallback and alternate font selection, keyboard access and no-JavaScript content. Extend the compatibility runner to exercise the new scale in Chrome and Firefox; preserve its explicit exclusions and diagnostics.
6. Document input ranges, formulas, ownership, role mappings, editing and observed proof in the existing handoff and a focused research addendum. Run focused tests, assets/design enforcement, canonical TEST `mix check`, `mix check.deep`, supported Hallmark and applicable browser regressions. Preserve failures and missing coverage. Generate history and obtain bounded independent source review before handoff. No merge, Done transition, visual-value approval or resulting-main certification.
